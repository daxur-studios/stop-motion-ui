# Stop-Motion UI

A POC for recording lightweight "replays" of UI interactions — without expensive video/gif capture.

## Core idea

- Capture sparse **screenshots** keyed to events (click, navigate, scroll/drag, animation start/end)
- Capture a **metadata stream**: cursor positions + timestamps + action types
- On playback, render a **fake animated cursor** that moves smoothly between recorded points (bezier easing, not linear)
- Sync whichever screenshot is "current" to the timeline as the cursor moves

Result: looks like a smooth screen recording, but is mostly stills + a cursor overlay — much smaller storage footprint than video/gif.

## Why

- Video/gif capture of UI walkthroughs is heavy (storage, encoding, playback)
- Most of a UI recording is static frames between discrete actions — recording every pixel of every frame is wasteful
- A manifest + screenshots + animated cursor can fake the "recording" feel at a fraction of the size

## Stack

- Plain Node.js + TypeScript for capture scripts — no framework
- Standalone HTML + Canvas page for the replay player — no Angular needed, this is a utility not an app
- Two capture backends for comparison: Chrome MCP and Playwright (see [`docs/adr/ADR-001-dual-capture-backends.md`](docs/adr/ADR-001-dual-capture-backends.md))

## Status

- **Replay player** (`replay/index.html` + `replay/player.js`): implemented. Loads a manifest + screenshots, animates a fake cursor along bezier-eased curves between recorded points, handles `circle` gestures as an orbiting motion, and has play/pause/scrub/speed controls plus a scenario picker. No real capture has happened yet, so it's validated against three hand-crafted fixtures in `replay/test-scenarios/` (placeholder screenshots generated by `generate_placeholders.py`).
- **Capture (chrome-mcp):** manifest-building logic proven via dry-run with synthetic data; no real screenshots yet.
- **Phase 1 (now):** click + navigate capture only, full capture → manifest → replay loop end-to-end at minimal scope
- **Phase 2 (later):** scroll/drag capture, animation-burst capture (multiple frames during a transition)

Opening `replay/index.html` directly via `file://` may fail to load manifests in Chrome (fetch is blocked cross-origin for the file scheme); serve the `replay/` folder over http instead, e.g. `python3 -m http.server` from inside it, or `npx serve replay`.
