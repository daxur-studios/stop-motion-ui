# Stop Motion UI demos

Use the installed `@daxur-studios/stop-motion-ui` dev dependency from the host repo. Read [the CLI and recipe guide](../../docs/agent-cli.md) for the API, narration contract and lifecycle details. Start from [the packaged example](../../examples/save-project.demo.mjs) when authoring a new recipe.

1. Read the host repo instructions and identify its app start command, demo URL and readiness signals.
2. Run `npx --no-install stop-motion-ui doctor --json`. Missing Chromium can be installed with `npx playwright install chromium`; ffmpeg and ffprobe must be available on the machine.
3. Choose `defineDemo` for reconstructed screenshot walkthroughs, or `defineVideo` for continuous games/animation. Use ordinary Playwright locators and application readiness signals. For screenshot mode, start with `demo.capture` and give each step a stable unique ID. For continuous mode, read [the continuous guide](../../docs/agent-cli.md#continuous-games-and-animation) and start from [its example](../../examples/continuous.demo.mjs): predeclare ordered segments and prepare/navigate the app in `ready(page)`. Keep recipes and narration text in the host repo.
4. Run `npx --no-install stop-motion-ui run demos/example.demo.mjs --out artifacts/videos/example --json`. Put generated videos in `artifacts/videos/<topic>/` in each repo and ensure `artifacts/` is gitignored. The tool privately manages its renderer; there is no scenario import into another checkout and no replay app to start.
5. Inspect `result.json`, the contact sheet and relevant full frames. Play the MP4 when the client supports it. Distinguish functional assertions, visual observations and audio checks. Deliver the returned video using the client method below and report limitations accurately.

In **Codex desktop/remote chat**, put `![Demo video](<absolute-path-to-demo.mp4>)` in the response, replacing the placeholder with the actual absolute file path (Windows: forward slashes). Keep the leading `!`; a plain link/path is only a fallback. The user confirmed phone playback of the pilot's H.264/AAC MP4 on 2026-11-05. No public host, separate upload call or replay app was used. In **Claude Code**, use its available `SendUserFile` tool with absolute `files`, `display: "render"`, `status: "normal"` and a caption. Antigravity is untested. See [delivery details](../../docs/agent-cli.md#discovery-and-delivery). Sharing alone does not require loading video into model context or establish content acceptance.

For speech, import `daxurSpeech` from the package and set `audioProvider: daxurSpeech({ voice: 'Fola' })` when the configured Daxur CLI is installed on PATH. Author narration on steps, without `audio` paths. The helper uses the supported `daxur generate gemini-speech` command; credentials and provider caching stay in Daxur. Keep each step within 2000 characters; changing text/voice/model invalidates local audio caching. See the guide for custom commands/model/timeouts. Supplied step `audio` paths remain supported and take priority. Select `--narration off` explicitly for a silent demo; it makes no speech calls. Missing requested speech is an error to fix or report. Use `capture` or continuous `run --keep-source` to retain intermediate inputs for rerendering without running the app again. Successful continuous `run` removes source frames by default; failed jobs can retain diagnostics.

Each run has an isolated output folder, so retries preserve earlier evidence and authored text. On failure, read the reported stage/step, `run.log` and any `scenario/failure.png` before retrying. Correct the actual failure; do not replace readiness conditions with guessed sleeps.

For continuous recipes, await `video.segment` and its `click`, `clickAt` or `moveTo` helpers. They initialize real/drawn pointer positions together, pace movement in wall time and press at arrival; raw locator/mouse actions bypass that guarantee. Keep input and speech at 1x. Mark parked-pointer waits/travel with `speed: 3` or `5`; the baked-in speed badge describes footage retiming, not simulation speed. Wait on actual game/app conditions, use `video.hold` only for presentation pauses, and prefer page-exposed semantic actions or projected bounds over walking a Three.js scene graph. The package prepares speech before capture and extends a narrated segment if needed. It records the browser page and supplied/generated narration, not game/system audio. `render` reuses a retained source scenario and `timeline.json` records source/output mapping.

HEVC/hvc1 is the compact default (phone playback confirmed 2026-11-06); use `--codec h264` for compatibility. `result.json.captureMode` distinguishes continuous page recording from screenshot reconstruction. Neither a preview nor a successful render verifies speech quality, remote playback or performance. Keep testing assertions and human visual acceptance separate.
